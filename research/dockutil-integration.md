## 1. `dockutil --list` Output Format

Exact format, confirmed from `Sources/DockUtil/Dock.swift:184-187`:

```swift
func printList() {
    forEach() {tile in
        print("\(printOptional(tile.label))\t\(printOptional(tile.url))\t\(tile.section)\t\(path)\t\(printOptional(tile.bundleIdentifier))")
    }
}
```

**Columns (tab-separated):**
1. `label` (`tile-data.file-label`; empty string if nil)
2. `url` (`tile-data.file-data._CFURLString` or `tile-data.url._CFURLString`; empty if nil)
3. `section` (`persistent-apps`, `persistent-others`, or `recent-apps`)
4. `plist` path (full path to the dock plist being read)
5. `bundle-identifier` (`tile-data.bundle-identifier`; empty if nil)

**How to parse:** Split each line on `\t`. When `--allhomes` or `--homeloc` is used, every line ends with the same plist path, which groups items per user. Empty fields still appear as empty between tabs.

**Source:** https://github.com/kcrawford/dockutil/blob/main/Sources/DockUtil/Dock.swift#L184-L187

## 2. Batching and `--no-restart`

**Multiple actions in one invocation: supported.**

From the 3.0.0 changelog (README + GitHub Releases):
> "Allow multiple actions in single run (add, remove can be combined and specified multiple times)"

The CLI accepts arrays for `--add` and `--remove`. In `DockUtil.swift`, additions and removals are processed in a single `for` loop per plist. A single boolean `restart` controls Dock termination. The default is `restart=true`. Using `--no-restart` sets it to `false`, deferring restart until the end (or never, if you pass `--no-restart`).

For DockSwap's "apply preset" flow, the safe pattern is:
- batch all adds/removes in one `dockutil` invocation
- omit `--no-restart` so dockutil does exactly one Dock termination at the end.

**Source:** https://github.com/kcrawford/dockutil/releases/tag/3.0.2

## 3. dockutil Plist Read/Write Keys

### Section keys (arrays at top level of `com.apple.dock.plist`)

| Key | Dock section | Enum value in source |
|-----|-------------|----------------------|
| `persistent-apps` | Apps bar | `DockSection.persistentApps` |
| `persistent-others` | Other items / stacks | `DockSection.persistentOthers` |
| `recent-apps` | Recent apps | `DockSection.recentApps` |

### Per-tile structure (each element in the arrays)

Top-level per-tile keys:
- `GUID` — integer, generated by dockutil as `Int.random(in: 1000000000..<9999999999)`
- `tile-type` — string: `file-tile`, `directory-tile`, `url-tile`, `spacer-tile`, `small-spacer-tile`, `flex-spacer-tile`

`tile-data` sub-keys, confirmed from live plist (`plutil -p` on this host) and `DockTile.swift`:

**File-tile (apps, stacks, documents):**
- `file-label` — display name
- `file-data._CFURLString` — POSIX path URL
- `file-data._CFURLStringType` — integer (`15` for `file://`, `0` for others)
- `file-type` — `41` for apps, `2` for directories, `1` for recent-apps
- `file-mod-date`
- `parent-mod-date`
- `dock-extra` — bool
- `bundle-identifier` — CFBundleIdentifier string
- `book` — opaque binary bookmark (`{length = ..., bytes = ...}`)

**URL-tile:**
- `label`
- `url._CFURLString`
- `url._CFURLStringType`

**Directory-tile extras:**
- `directory` — `1`
- `arrangement` — `name|dateadded|datemodified|datecreated|kind`
- `displayas` — `1` = folder, `0` = stack
- `showas` — `0`=auto, `1`=fan, `2`=grid, `3`=list
- `preferreditemsize`
- `showas` / `showas` is for folder view mode.

### How dockutil reads

For the **logged-in user's dock** (console user, current user): uses `CFPreferencesCopyAppValue` for each section — this reads the cfprefsd cache, NOT disk directly.

For **other users / non-console-user**: runs `/usr/bin/defaults export <path> -`, then `PropertyListSerialization.propertyList(...)` on the binary plist output. It explicitly comments:
> "Read using defaults because we can't trust what is on disk and defaults uses cfprefs cache"

### How dockutil writes

- Console user: `CFPreferencesSetAppValue` + `CFPreferencesSynchronize`, then `NSWorkspace` terminate or `killall Dock`.
- Non-console user: `defaults import <path> -` via `sudo -u <ownerUID>` (because direct disk writes would be ignored by cfprefsd), then `killall Dock`.

**Source:** https://github.com/kcrawford/dockutil/blob/main/Sources/DockUtil/Dock.swift#L53-L177, `DockTile.swift`, live `plutil -p` on this host.

## 7. Reading the Dock Plist Directly with Swift — Viable Alternative for Capture?

**Yes, with an important caveat.**

dockutil itself does NOT read disk for the console user's dock. It uses `CFPreferencesCopyAppValue(..., "com.apple.dock")` which reads from the cfprefsd daemon cache. This is the same cache the Dock itself uses. Reading the raw file on disk (`/Users/<user>/Library/Preferences/com.apple.dock.plist`) can give stale data if cfprefsd hasn't flushed yet.

For **capturing current dock state**:

- **`CFPreferencesCopyAppValue` / `CFPreferencesCopyKeyList`** is the most accurate way, matching what dockutil does for the console user. Requires running as that user.
- **`PropertyListSerialization` on disk plist** is simpler but can lag behind the live cache. Viable for a non-critical "capture now" snapshot, and it's what dockutil falls back to for non-console users.
- For DockSwap running as the current user, `CFPreferences` APIs are the right call. The `book` key in each `tile-data` is binary and not portable; you don't need to deserialize it to capture labels/paths/identifiers.

For **writing**: direct disk writes are ignored by cfprefsd; dockutil's non-console-user path uses `defaults import` via `sudo -u <owner>`. So DockSwap should not write to disk directly either — it must go through cfprefsd or `defaults`.

**Source:** `Dock.swift:53-91` (read logic), `Dock.swift:93-177` (write logic), live plist inspection.

## Summary of Key Findings

- **`--list` format:** `label<TAB>url<TAB>section<TAB>plist<TAB>bundle-id` — trivial to parse.
- **Batching:** Yes, multiple `--add`/`--remove` in one call with one restart at end. `--no-restart` defers termination.
- **plist structure:** `persistent-apps`, `persistent-others`, `recent-apps` arrays; each item has `GUID`, `tile-type`, `tile-data` with `file-label`, `bundle-identifier`, `file-data._CFURLString`, `file-type`, `dock-extra`, plus opaque `book` binary.
- **Min macOS / license:** 10.15 SPM target, README says Big Sur+ for 3.x, Apache-2.0.
- **Homebrew:** stable 3.1.3 available, tahoe+sequoia+sonoma+ventura bottles, not installed here.
- **Known issues:** 14.4 kickstart fixed in 3.1.3; Sonoma `--no-restart`/BPT trap and `defaults` hangs (issues 153/126/160) remain open; no Tahoe/Sequoia-specific issues found yet.
- **Direct plist read:** viable for capture if using `CFPreferences` APIs (not raw disk file); direct disk writes are NOT safe for write paths.
